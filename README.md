# وب‌سایت نماد نیرو

سایت شرکت نماد نیرو — ساخته‌شده با [Astro](https://astro.build). بدون وردپرس، بدون PHP.

همهٔ صفحات در زمان بیلد ساخته و به‌صورت HTML ثابت سرو می‌شوند. فقط دو مسیر روی سرور اجرا می‌شوند: `/api/quote` (دریافت فرم مشاوره) و `/leads` (پنل مشاهدهٔ درخواست‌ها). به همین دلیل میزبان باید **Node.js** را اجرا کند، نه PHP.

---

## اجرا روی سیستم خودتان

```bash
npm install       # فقط بار اول
npm run dev       # http://localhost:4321
```

ساخت نسخهٔ نهایی:

```bash
npm run build     # خروجی در پوشهٔ dist/
npm run preview   # پیش‌نمایش خروجی نهایی
```

## افزودن و ویرایش محتوا

### مقالهٔ جدید (مجله)

یک فایل تازه در `src/content/articles/` بسازید، مثلاً `my-article.md`:

```markdown
---
title: "عنوان مقاله"
category: edu        # edu | market | news
date: "۱۴۰۴/۰۵/۱۲"
readTime: 5
draft: false         # true یعنی منتشر نشود
---

متن مقاله اینجا نوشته می‌شود. می‌توانید **بولد**، فهرست و تصویر بگذارید.
```

صفحهٔ مقاله، لینکش در فهرست مجله و بخش «مطالب مرتبط» خودکار ساخته می‌شود.

### محصول جدید (فروشگاه)

به `src/data/products.json` اضافه کنید:

```json
{
  "id": "شناسه-یکتا",
  "name": "نام محصول",
  "brand": "SUNGROW",
  "spec": "۱۰",
  "specUnit": "kW · سه‌فاز",
  "cat": "industrial",   // home | industrial
  "kind": "inverter",    // inverter | panel | storage | accessory
  "featured": false,     // true یعنی در صفحهٔ اصلی هم بیاید
  "order": 17
}
```

### پروژهٔ جدید

به `src/data/projects.json` اضافه کنید:

```json
{
  "id": "شناسه-یکتا",
  "name": "نام کارفرما",
  "capacity": "۵",
  "unit": "MW",
  "tag": "تأمین پنل",
  "cat": "supply",       // supply | build | invest
  "note": "توضیح کوتاه",
  "featured": false,
  "order": 30
}
```

### متن‌های ثابت سایت

منو، آمار، حوزه‌های فعالیت، برندها و کارفرمایان همگی در یک فایل هستند:
`src/data/site.ts`

## تصاویر

تصاویر محتوایی در `src/assets/` قرار دارند تا Astro آن‌ها را **خودکار بهینه کند**
(تبدیل به WebP، ساخت اندازه‌های مناسب موبایل و دسکتاپ، و بارگذاری تنبل).
برای جایگزینی، فایل هم‌نام را عوض کنید — بقیهٔ کارها خودکار انجام می‌شود.

فقط فایل‌هایی که باید آدرس ثابت داشته باشند (لوگو و لوگوی برندها) در
`public/assets/` مانده‌اند.

| فایل | کاربرد | ابعاد |
|---|---|---|
| `activity-1/2/3.jpg` | اسلایدر صفحهٔ اصلی | ۲۵۶۰×۱۰۶۷ (نسبت ۲٫۴:۱) |
| `banner-1/2.jpg` | بنر صفحهٔ اصلی | ۱۶۰۰×۴۰۰ |
| `area-1/2/3.jpg` | صفحهٔ حوزه‌های فعالیت | ۱۲۰۰×۹۰۰ |
| `project-1/2/3.jpg` | پروژه‌های منتخب | ۹۰۰×۱۱۰۰ و ۱۲۰۰×۷۲۰ |
| `brands/*.png` | لوگوی برندها | ~۳۰۰×۱۲۰ |
| `products/*.jpg` | عکس صفحهٔ هر محصول | مربعی، حداقل ۷۰۰×۷۰۰ |

عکس ۷ محصول (فرونیوس، سانگرو، سانویز، AE Solar) از سایت فعلی نمادنیرو گرفته شده. برای محصولات Deye، Goodwe، Sineng و Trina — که در فروشگاه فعلی سایت زنده وجود ندارند — هنوز عکس واقعی نداریم؛ تا وقتی عکس اضافه نشود، به‌جای عکس، نام برند نمایش داده می‌شود (طبق همان الگوی fallback فعلی).

## فرم درخواست مشاوره (Quote Form)

فرم روی صفحهٔ اصلی (`#quote`) و صفحهٔ «تماس با ما» داده را به `/api/quote` می‌فرستد — یک مسیر داخل خود پروژه، بدون وابستگی به هیچ سرویس بیرونی.

هر درخواست **اول ذخیره می‌شود، بعد ایمیل می‌رود**؛ بنابراین اگر سرویس ایمیل از کار بیفتد، هیچ درخواستی گم نمی‌شود.

### متغیرهای محیطی

این مقادیر در پنل میزبان تعریف می‌شوند و هرگز داخل کد یا مخزن قرار نمی‌گیرند:

| متغیر | کاربرد |
|---|---|
| `LEADS_DIR` | مسیر ذخیره‌سازی درخواست‌ها. باید روی یک **دیسک پایدار** باشد، وگرنه با هر انتشار پاک می‌شود. |
| `LEADS_USER` / `LEADS_PASS` | نام کاربری و رمز ورود به پنل `/leads` |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | تنظیمات ارسال ایمیل |
| `MAIL_TO` | گیرندهٔ درخواست‌ها (پیش‌فرض: `sales@namadniroo.ir`) |
| `MAIL_FROM` | فرستنده (پیش‌فرض: همان `SMTP_USER`) |

اگر تنظیمات SMTP وارد نشده باشد، فرم کار می‌کند و درخواست ذخیره می‌شود، ولی ایمیلی ارسال نمی‌گردد.

اگر `LEADS_USER` و `LEADS_PASS` تعریف نشده باشند، پنل `/leads` **بسته می‌ماند** (خطای ۵۰۳) — نه اینکه بدون رمز باز شود.

## انتشار

سایت یک اپ **Node.js** است: صفحات از پیش ساخته می‌شوند و به‌صورت استاتیک سرو می‌گردند،
ولی برای دو مسیر سمت‌سرور (`/api/quote` و `/leads`) به یک فرایند Node نیاز است.

```bash
npm ci
npm run build     # خروجی در dist/client و dist/server
npm start         # اجرای سرور (PORT و HOST از متغیر محیطی خوانده می‌شوند)
```

میزبان باید:

- Node.js نسخهٔ ۲۰ یا بالاتر اجرا کند
- `npm run build` و سپس `npm start` را صدا بزند
- یک **دیسک پایدار** برای `LEADS_DIR` فراهم کند تا درخواست‌ها با هر انتشار پاک نشوند

> روی میزبان‌های ابری فایل‌سیستم موقتی است. اگر دیسک پایدار وصل نشود،
> درخواست‌های ثبت‌شده با اولین انتشار بعدی از بین می‌روند.

## پنل درخواست‌ها

`namadniroo.ir/leads` — فهرست درخواست‌ها با آمار و خروجی CSV.

ورود با نام کاربری و رمزی که در متغیرهای `LEADS_USER` و `LEADS_PASS` تعریف می‌کنید.
اگر این دو تعریف نشده باشند، صفحه بسته می‌ماند و هیچ داده‌ای نشان نمی‌دهد.

درخواست‌ها در `LEADS_DIR/leads.jsonl` ذخیره می‌شوند — هر خط یک رکورد JSON.
این فایل مستقیماً از طریق وب قابل دسترسی نیست و برای پشتیبان‌گیری کافی است
همین یک فایل را کپی کنید.

## نکات فنی

- **راست‌چین (RTL):** سراسر سایت. جهت حرکت اسلایدرها دستی مدیریت شده است.
- **فونت:** دانا، از `public/fonts/`، به‌صورت متغیر (وزن ۱۰۰ تا ۹۰۰).
- **رنگ‌های برند:** در `:root` فایل `global.css` — زرد `#FFC41A`، سرمه‌ای `#0A3D5D`.
- **دسترس‌پذیری:** فوکوس با کیبورد، احترام به `prefers-reduced-motion`.
- **فروشگاه:** فعلاً لیدجن است («استعلام قیمت»). فیلدهای `price`، `sku` و `inStock` در ساختار داده آماده‌اند تا در آینده سبد خرید اضافه شود.
